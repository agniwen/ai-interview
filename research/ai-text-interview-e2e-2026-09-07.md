## 发现及修复

### 开场确认泄漏工具旁白

第二轮浏览器在确认准备后，曾显示内部叙述“候选人已明确表示准备好开始面试。我将调用 confirm_ready 工具”。后续题目流程正常，但该文字不应向候选人展示，也不应进入语音输出。

原因是独立的 `ReadyCheckTask` 提示词仅规定何时调用工具，没有约束工具调用前的可见输出；父面试 Agent 的其他规则不会自动传入这个独立任务。

最小修复位于 `apps/livekit-agent/src/ready_check_task.py`：要求阶段切换只产生工具调用，由下一阶段负责提问或告别；禁止输出工具名称、调用计划及内部判断。

按仓库 Voice Agent 指南先添加 `tests/test_ready_check_task_llm.py`，使用与运行 Worker 相同的模型配置，覆盖两种准备答复和明确退出。旧提示词下 3 例中 2 例出现额外可见话术；该单测基线没有复现浏览器完全相同的工具名称句子。修改后 3 个真实模型测试与 4 个既有单测共 7 项通过；Ruff 格式、检查及 scoped diff 检查通过。

在线模型测试仅在显式设置 `RUN_AGENT_LLM_TESTS=1` 时执行，不创建房间、不发送面试回调。提示词不能证明所有随机生成都绝无泄漏，仍需真实 UI 验证：第三轮使用新 Worker，于 02:00:45 确认准备后直接进入第一题，未出现工具旁白。

当前安装版本的旧 Python CLI `src/agent.py dev` 已移除自动重载，不能仅凭 dev 命令判断变更已生效。本次没有中断正在进行的第二轮，在第三轮使用新 Worker 验证修复。

## 异步链路与验证边界

1. 浏览器面试和 Agent 回调是真实链路。接收报告后，Server 在本进程异步生成摘要、评价和关键资料；本机未启用通知 Worker flags，因此本次不以 Worker 作为报告生成依赖。
2. 三条测试副本的 `recruiting_record.created_by` 临时置空，阻止自动飞书卡片及邮件。原值保存于本机 `/tmp/ai-e2e-original-creators.json`；复制源未修改。需要保留这一隔离，直到明确决定恢复通知；恢复后全局重试可能补发。
3. **飞书文档采用定向 document-only 脚本生成，不代表自动通知链路通过。** 脚本在摘要 ready 后调用现有 `ensureInterviewEvaluationDocument`，生成文档并存储 URL，未调用通知编排、发卡片或邮件函数。
4. 文档存储复用投递表，投递状态真实保持 `pending`，`feishu_message_id`、`sent_at` 均为空；没有伪造 sent。不要对这些测试记录点击人工重发，也不要以全库 retry 验收此任务。
5. 文档内容经过远端重新读取验证；文件夹归档使用现有 provider 的配置逻辑，未额外测试通知触达、接收者设备显示或全部共享权限。
6. 本次文字输入覆盖模型对话、工具调用、结果回调和异步报告，不代表麦克风识别、真实音频播放、断网重连等路径全部通过。
