## 环境与方法

- 分支 `feat/realtime-agent`，本地 Web + `make agent-dev`，实际 Qwen 和 LiveKit 服务。
- 经授权使用产品测试工作区 `starrail`，招聘记录 `bedca0d4-cee0-4059-b5ea-da5057b20016`，轮次 `d12cab51-b547-42f1-9d1c-1aef774b9917`。
- 使用合成候选人语音，经产品公开 token 接口、真实 WebRTC 麦克风音轨、实际 Agent 工具和业务回调生成报告。在管理页面用“选择面试记录”切换核对结果。未模拟物理麦克风、扬声器回声、移动端和真实环境噪音。
- 音色 `longanlingxin`，关闭情绪增强；音色主观感受仍应由真人试听确认。

## 修复与报告复核

- 历史记录选择器原先只统计旧 `done` 状态，漏掉 `completed`，造成“已完成 0”；现兼容两者并添加回归测试。
- 更正口误不应被报告推断成薪资诉求变化或稳定性风险；新完整轮次已验证最终薪资引用正确。
- 完整轮次的报告仍将“没有补充，可以结束”误解为中途结束，并提及本次未要求的到岗时间。已进一步收紧正常收尾和缺失信息范围规则；用该轮真实转写重新调用报告模型，返回“整体面试流程完整”，未再声称提前退出。验证输出位于 `/tmp/ai-interview-voice-probe/report-regenerated.json`；未覆盖历史报告，UI 中历史文字仍保留原生成结果。
- 第三轮暴露 Agent 实际追问岗位信息却未调用话题标记工具，导致最终归为未提问。新增真实模型回归先失败，再强化“提问前先 set_active_topics、零散事实及时保存”的规则后通过；同时验证“准备好了”不会产生虚构答案。
- 第四轮发现收尾工具将退出请求作为最后答案并自动标 answered。增加工具层校验：只有 completed 可以携带最后答案，提前退出/超时必须先独立保存真实事实，再以空 final 字段结束。回归先失败、修复后通过。
- 第五轮确认退出意图不再自动标 answered，但“负责订单服务”被放入当前求职动机题的不足摘要，未归入工作经历题。原始转写与报告汇总保留事实；主题归类仍有不确定性，后续应增加以最终转写核对题目归属的步骤，不能宣称工具状态完全可靠。
- 第五轮 UI 逐题分析还引用了面试前表单的 `oyu`，原始语音并未说该内容。这说明表单与语音题评估的来源隔离仍不够：后续应将可用于 HR 汇总的表单上下文与逐题语音评分输入分开。该轮产生 20/100，不能解释为能力评估已可靠。
- 现有评分规则会将明确跳过计 0 分，部分沟通轮次产生 23/100。建议分开呈现信息覆盖率和有证据的能力评分；本次未更改评分口径。
