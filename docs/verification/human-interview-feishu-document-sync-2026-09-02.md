# 真人面试最终评价回填飞书

## 行为

- 面试官正式提交时，在同一事务内保存最终评价、不可变快照和文档同步任务。草稿、AI 自动评价生成和 HR 单独标记轮次完成不创建同步任务。
- 首次处理按候选记录及工作区查询 `summary_ready` 通知，以 `updated_at DESC, id DESC` 选择最新文档，同时保存文档 ID、URL 和飞书应用。任务后续重试保持该目标。
- 无文档时保留 `waiting_document`，一分钟后重新检查；同步失败按退避重试，最长一小时。面试官页面展示状态，并允许重试失败或等待文档的任务。
- 使用实际轮次名创建独立区块，保留面试官确认的评价原文、结论、提交人和提交时间。记录区块 ID 后再填充正文，重试复用本轮区块，保留其他区块和模板人工内容。已被删除的区块报错，不擅自重建。
- 同一文档的不同轮次在数据库中串行认领；任务十分钟后可被重新接管，远端操作整体截止时间五分钟，单次请求三十秒。网络请求期间不保持数据库事务。
- 服务端禁止已提交或已结束轮次再次保存草稿、提交评价或请求重新生成，防止旧页面覆盖最终内容。

## 运行与部署

1. 执行 `apps/web/drizzle/20260902170000_human_interview_document_sync/migration.sql` 对应迁移，再发布 Web／Server。
2. 同步由 Web 承载的后端执行，复用 Web 的 `DATABASE_URL` 和现有飞书应用凭据；独立 Server 模式复用 Server 的配置。目标文档所属应用的凭据必须有效。
3. Web 的 Nitro 运行时插件启动轮询；独立 Server 在启动时注册同一调度器。每十秒检查持久化任务，启动后立即处理，无需新的 HTTP 请求。预渲染不启动轮询，运行时关闭钩子及 Web 进程停止信号停止轮询并等待正在执行的任务结束；进程异常退出由数据库租约恢复。
4. Worker 不再执行文档同步，也不再为此配置飞书凭据或打包文档同步模块。同步不依赖 Worker、Redis、通知模板、通知流程或机器人连接开关。
5. 本次没有自动回填历史已提交评价；新提交自动创建任务。

## 验证

- 临时独立 PostgreSQL 实例从仓库迁移初始化，未操作业务数据库。
- 执行入口迁移后，Server 的调度、任务认领、文档写入、重试权限和关闭流程定向测试 19 项通过；Web 面试官评价页面及服务入口测试 29 项通过。
- 回归用例先复现旧页面保存草稿和强制重新生成覆盖已提交评价，再验证修复。
- 验证最新文档及应用选择、缺失文档等待、目标固定、区块恢复、失败状态、并发认领、失效任务接管、跨工作区隔离、旁听者拒绝重试。
- Server、Worker、Web 类型检查通过；Web 完整构建及服务端依赖导入检查通过；修改范围内格式/lint 检查及 `git diff --check` 通过。
- 使用同一临时 PostgreSQL，分别启动 Web 构建产物和独立 Server；不发送 HTTP 请求，预置任务均从 `pending` 转为 `waiting_document`，证明运行时启动后会自行处理持久化任务。同时验证 Web 收到 SIGTERM 后停止轮询并正常退出。测试完成后清理临时记录并停止服务。
- 飞书调用使用协议模拟测试，未向真实文档发送写入请求。

## 复审修复

- 正式提交时按“会议转录 → 面试轮次”的顺序加锁，转录版本校验、最终评价、快照和同步任务在同一事务内完成；没有处理会话的人工评价仍可提交。
- 区分“任务暂缓”和“无到期任务”，缺少文档或同文档已有同步任务时继续扫描，每轮仍最多处理十条，避免无界轮询。
- 新增独立数据库回归：提交事务未结束时，并发转录更新必须等待；提交完成后可以更新。新增真实 DAO 与调度器回归：首条任务缺文档，下一条可同步任务仍在同一轮完成。两个用例均先复现失败，再验证修复。
- 修复后的定向测试共 36 项通过，包含无转录人工提交、已提交保护、任务重试、同文档串行、调度关闭和上述两项回归。
