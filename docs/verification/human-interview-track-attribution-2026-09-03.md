# 真人面试分轨与身份归属验证

## 处理范围

- Web 真人面试保留自己的入会/结束流程；录音入库后复用 Meeting Buddy 的转录、版本、评价队列，不修改 Desktop 双轨采集。
- 全场录音与授权参会者的麦克风分别录制为 OGG。候选人身份来自服务端候选人邀请，其他非旁听面试官来自服务端参会清单，不信任 ASR 聚类编号或客户端展示名。
- 音轨重连使用新 track SID、新文件。启动抢占与回调状态更新在短事务内串行化，外部 Egress 请求在事务外执行。
- Worker 每分钟补查录音状态。会议结束后等待录音落盘；超过 5 分钟仍未完成的录音转入失败补救，不无限阻塞手动评价。
- 优先转录独立音轨，只对缺失时段使用全场录音恢复。未归属片段不作为候选人能力证据；缺录、漏识别不能作为降低能力评价的理由。
- 全场补救片段能排除候选人时标记面试官，否则待确认。排除依据是经过大小、时长、音频可解码校验的候选人文件在整个片段（前后各留 300ms）具有近数字静音，并且所有重叠候选人文件一致。候选人有任一文件校验失败就禁用该自动排除；没有 ASR 文本不代表静音。静音检测失败也不提供排除证据。
- 待确认片段可单独回听、人工确认。确认生成新转录版本，保留原始版本与来源；不会自动改写评价或触发飞书通知，需要面试官主动重新生成评价。

## 数据与配置

- 已向当前开发配置数据库执行 `20260903110000_human_interview_track_recording`，并只读复核三个新增 JSONB 字段：录音清单、录音身份、转录归属。
- 自动化数据库测试使用一次性本地 PostgreSQL，不向共享开发库写入测试会议。
- Worker 的本地 LiveKit 连接已与 Web 对齐；部署时 Worker 也必须配置 `LIVEKIT_URL`、`LIVEKIT_API_KEY`、`LIVEKIT_API_SECRET`，并与 Web 使用相同数据库、队列、录音存储。

## 验证结果

- 全仓格式/静态检查、类型检查通过；独立服务器入口可导入。
- Web 771、Worker 149、Desktop 260 个测试通过；Python lint、格式检查及 150 个测试通过。
- 已补录音缺失补救、候选人静音排除、重复回调与重连、人工归属的权限/跨会议保护、原始版本不可变及来源防伪回归测试。
- 全量 Server 测试仍有三个既存架构约束失败：Worker 已有 Server 依赖、既有 `web/document-sync` 导出、既有复核路由直接使用数据库。已对照 HEAD 确认这些结构原先存在，未放宽测试规则。鉴权用例最初缺测试 OAuth 配置，补测试占位值后单独通过。

## 真实联调待验证与边界

- 未替用户启动麦克风、创建测试会议或主动发起真实 ASR/面试评价/飞书测试。必须用新会议验证实际 Egress 音频、时间对齐与最终转录；旧会议不能凭空补出未录制的面试官独立音轨。
- 最终健康检查发现 Worker 已退出，已单独恢复并加载新的本地 LiveKit 配置，未重启 Web/Agent/LiveKit。启动恢复扫描未发现待处理的真人面试录音/评价，但接续了一个已有通用会议分析任务。
- 超时后才到达的录音完成事件会保留清单状态；如果本轮已完成入库，不自动替换已生成的转录和评价。
- 归属表示授权麦克风的来源，不是声纹鉴定。同房间串音、扬声器回灌、共享设备或麦克风本身未采到声音仍可能影响归属；真实测试应使用耳机并避免同一声音被两端重复采集。
