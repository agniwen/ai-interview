# 百度中文简历解析能力调研

日期：2026-08-03

证据基线：百度智能云/百度 AI 开放平台官方产品页、API 文档和协议；项目适配判断来自本仓库源码。未使用第三方评测或转述。

## 结论

**建议把百度接入目标定为“智能文档分析平台—文档抽取”，不要新接旧版“语言与知识—简历解析”接口。**

原因很明确：百度仍保留专用[简历解析 API 文档](https://cloud.baidu.com/doc/NLP/s/Xkahvfeqa)，但页面已明确标注“已停止更新且即将下线”。当前公开文档中，可自助领取额度、按量购买且最接近“上传完整简历后直接得到结构化字段”的能力，是[智能文档分析平台的文档抽取 API](https://cloud.baidu.com/doc/OCR/s/klzkwzdch)：它用大模型按自定义字段清单或 Prompt 抽取内容，支持组合字段和原文位置，并以异步任务返回结果。

百度另有[招聘行业大模型解决方案](https://cloud.baidu.com/solution/zhaopin.html)，明确覆盖简历解析与打标，但公开入口是“立即咨询/量身定制”，没有独立的标准 API 契约、价格或自助开通文档；因此它适合商务 PoC 备选，不应作为当前代码集成所依赖的公开 API。

建议的产品优先级：

1. **主选：智能文档分析平台—文档抽取**。公开、自助、可商用，能用字段清单表达本项目 DTO；需新增异步轮询、字段映射、类型归一化与 Zod 校验。
2. **商务备选：招聘行业大模型解决方案**。若百度能在书面方案中给出专用招聘模型、SLA、数据删除承诺和价格，可做封闭 PoC 后再比较。
3. **不建议：旧版专用简历解析 API**。虽最贴近固定招聘 DTO，但官方已宣告停止更新和即将下线。
4. **暂不主选：iOCR 全场景识别**。能力也可自定义抽取，但 API 官方仍标注“邀测”，需提交公司、App ID 和场景后人工开通；不如文档抽取具备确定的自助商用路径。[官方 API 文档](https://cloud.baidu.com/doc/OCR/s/9m85k00pn)

## 推荐 API：文档抽取

### 调用与认证

文档抽取是两段式异步 REST API：

1. `POST https://aip.baidubce.com/rest/2.0/brain/online/v1/extract/task`，提交文件和抽取定义，返回 `taskId`。
2. `POST https://aip.baidubce.com/rest/2.0/brain/online/v1/extract/query_task`，携带 `taskId` 轮询结果。

两者均使用 `application/x-www-form-urlencoded`；通过百度云应用的 API Key、Secret Key 向 `https://aip.baidubce.com/oauth/2.0/token` 换取 `access_token`，再把 token 放入 API URL 查询参数。官方说明 token 有效期 30 天，应按 `expires_in` 缓存并定期更新。[官方：OCR 调用与鉴权](https://cloud.baidu.com/doc/OCR/s/Ck3h7y2ia)

官方建议提交后 30 秒开始轮询；提交接口限制 2 QPS，查询接口限制 10 QPS。因此本项目已有的 BullMQ 异步处理适合承接此接口，但不能把它包装成请求内同步调用。[官方：文档抽取接口描述](https://cloud.baidu.com/doc/OCR/s/klzkwzdch)

### 请求

文件可用以下二选一方式提交：

- `file`：去掉 data URL 头的 Base64；同时传 `fileName`。
- `fileURLs`：单个可下载 URL，长度不超过 1024 字节。

支持格式与限制：

| 类型        | 支持格式/限制                                                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 图片        | `jpg/jpeg/png/bmp/tif/tiff`；最短边至少 15 px、最长边最大 4096 px                                                                       |
| 文档        | `doc/docx/pdf/xlsx/xls/ofd`                                                                                                             |
| 文件数/大小 | 每次仅一篇，不超过 50 MB                                                                                                                |
| 抽取定义    | `manifestVersionId`、`manifest`、`prompt` 三选一；优先级依次降低                                                                        |
| 字段清单    | `manifest` 中每项有 `key`、可选 `parentKey`、可选 `description`；最多 100 个 key；key/parentKey 最多 30 字符，description 最多 100 字符 |
| 模型场景    | 默认长文档；可选 `Extract_Scene_Long_Doc_LLM` 或 `Extract_Scene_Long_Doc_VLM`                                                           |

还可设置 `useParseResult`、字段值去重、指定页、印章抽取、去水印和图像矫正；对于 `doc/docx/wps/xls/xlsx`，官方提示流式文档页码解析不固定，指定页抽取宜优先用于 PDF/OFD/图片。[官方：文档抽取请求参数](https://cloud.baidu.com/doc/OCR/s/klzkwzdch)

### 响应

提交成功返回 `taskId`。查询结果的状态为 `Pending`、`Running`、`Success` 或 `Failed`，并带创建、开始、完成时间和任务耗时。成功时主要数据位于：

- `extractLabelInfo`：本次字段清单；
- `extractResult[].data.singleKey`：单字段的 `word` 与原文位置；
- `extractResult[].data.comboKey`：组合字段及各子字段位置；
- `extractResult[].pdfUrl`：源文件转换 PDF 后的 BOS 下载链接，官方只承诺有效 30 分钟。

返回的是“字段名 → 抽取值/位置”的产品结构，不是本项目 `ResumeParserStructured` 的 JSON 形状。[官方：文档抽取查询响应](https://cloud.baidu.com/doc/OCR/s/klzkwzdch)

### 价格与试用

官方 2026-06-10 价格页显示：个人认证和企业认证均可自动领取 **200 页、365 天有效**的免费资源；按量后付费为 **0.2 元/页**，只计成功调用；预付资源包从 1,000 页 200 元起，阶梯下降至 500 万页 45 万元，资源包有效期一年。[官方：智能文档分析平台价格](https://cloud.baidu.com/doc/OCR/s/tlrzzplc1)

按 2 页/份简历粗算，公开按量价约 0.4 元/份；这是页数假设下的推算，不含本项目后处理、重试、存储和人工复核成本。

## 与现有 OCR + LLM 的区别

| 维度           | 本项目 `ocr-llm`                                                  | 百度文档抽取                                                                     |
| -------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 流程控制       | 项目分别控制文本/版面提取、Prompt、LLM、重试与校验                | 百度托管解析与大模型抽取，项目提交清单或 Prompt                                  |
| 输出契约       | 直接以本项目 Zod schema 为目标，项目可重试修复                    | 返回百度的 single/combo key 结构，必须再适配为项目 DTO                           |
| 原文证据       | 取决于现有 OCR 文本和项目实现                                     | 字段可返回页码与坐标；直接 VLM 且关闭解析时官方注明没有定位信息                  |
| 延迟模型       | 当前为项目内部组合调用                                            | 固定异步任务；官方建议 30 秒后开始轮询                                           |
| 文件覆盖       | 当前代码接受 PDF、DOC、DOCX、HTML、PPT、PPTX、XLS、XLSX、JPG、PNG | 不接受 HTML/PPT/PPTX；新增 BMP/TIF/TIFF/OFD                                      |
| 可观测与可复现 | 可记录模型、Prompt、原始 OCR 和 token 使用                        | 能记录 taskId、状态、时长和字段位置，但公开文档未提供底层模型版本固定/可复现承诺 |
| 供应商边界     | OCR 与 LLM 可分别更换                                             | 文档解析与抽取绑定百度能力和按页计费                                             |

百度文档抽取不是旧专用简历解析 API 的一比一替代：旧 API 会直接输出基本信息、教育、工作、项目、补充信息等固定招聘字段，并做“最高学历”“累计工作年限”等归一化；文档抽取只按清单/Prompt 抽取字段。项目仍需决定日期、工作年限、学历、技能数组、时间线风险等派生规则。[官方：旧版简历解析字段](https://cloud.baidu.com/doc/NLP/s/Xkahvfeqa)

## 字段映射与风险

本项目目标类型在 `packages/db-schema/src/resume-parser-schema.ts`。推荐首轮清单映射如下：

| 项目目标                                             | 百度清单设计                                                          | 风险/后处理                                                |
| ---------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------- |
| `name/phone/email/gender/age`                        | 单字段                                                                | `age` 需字符串转数值；缺失值统一为 `null`                  |
| `degree/education/major/graduationYear`              | 单字段 + 教育组合字段                                                 | “最高”值不能只信单字段；应根据教育数组再计算/核对          |
| `educationExperiences[]`                             | `教育经历` 组合字段：学校、专业、学历、学位、起止时间、毕业年份、摘要 | 组合行对齐、在读/交换经历、多个学历排序需样本验证          |
| `workExperiences[]`                                  | `工作经历` 组合字段：公司、职位、起止时间、摘要                       | 同一公司多岗位、实习与全职、并行任职可能错组               |
| `projectExperiences[]`                               | `项目经历` 组合字段：名称、角色、起止时间、摘要、技术栈               | `techStack` 需要字符串拆数组；工作内项目可能与独立项目混淆 |
| `skills/personalStrengths/targetRoles/links/schools` | 单字段或 Prompt 模式后拆数组                                          | 分隔符、去重、技能与自我评价边界不稳定                     |
| `workYears`                                          | 可抽原文工作年限，但最终由时间线计算                                  | 不应直接采用模型推断数字；需处理空档、重叠和实习           |
| `timelineSummary.*`                                  | 不建议直接作为抽取字段                                                | 属于跨经历推导；继续由项目规则/结构化后处理生成            |

主要风险：

- `manifest` 最多 100 个 key，虽足够当前 schema，但它表达的是父子组合，不等同于任意嵌套 JSON Schema。
- 百度没有在公开 API 文档中承诺字段数据类型、枚举或本项目 JSON schema 约束；必须保留 `structuredSchema.safeParse`、规范化和一次有界修复策略。
- 文档抽取不支持当前入口允许的 HTML、PPT、PPTX；应在 provider 选择前做能力路由，不能因切换 provider 退化为全局拒绝。
- 30 秒后才建议开始轮询，吞吐还受 2 QPS 提交限制；批量导入必须用队列、指数退避/抖动和任务超时，而不是前端长连接硬等。
- Prompt 模式更接近现有阿里云文档挖掘，但结构稳定性风险高于清单模式；首个 PoC 建议用版本化 `manifestVersionId`，另存清单版本与 provider 元数据以保证审计。

## 实施改造点（不含本次代码修改）

1. 在 provider 枚举中新增独立值（建议 `baidu-document-extract`），不要复用 `ocr-llm` 或伪装成旧“百度简历解析”。
2. 新建后端独立 adapter：token 缓存、提交任务、轮询、超时/取消、错误分类、响应映射；保持 Hono 后端可独立运行。
3. 在 BullMQ Worker 环境同步新增百度凭证和 provider 配置；凭证只保存在服务端，例如 `BAIDU_OCR_API_KEY`、`BAIDU_OCR_SECRET_KEY`。
4. 用版本化字段清单映射到 `ResumeParserStructured`，然后复用现有 Zod 校验、日期/年限/数组归一化和一次修复重试。
5. 扩展 `parsedTextSource`/数据库枚举、缓存兼容判断和管理端来源标签；百度结果不可与其他 provider 的同哈希缓存混用。
6. 文件能力路由：百度支持的格式走新 provider；HTML/PPT/PPTX 明确回退现有 `ocr-llm`，或先做可信格式转换。
7. 记录 `taskId`、清单版本、页数、耗时、错误码、重试次数和原始响应引用；不要长期保存 30 分钟有效的临时 `pdfUrl`。
8. 在现有 benchmark/eval 语料上做盲测，至少比较字段完整率、经历分组准确率、日期/年限准确率、P95 延迟、失败率和真实每份成本；达标后再开放为生产 provider。

## 安全、SLA 与数据留存

### 官方可确认

- 智能文档分析产品页称已通过等保三级、ISO 27001 等认证；产品页称系统可靠性可达 99.9%。这属于产品声明，不等同于带赔付条款的专项 SLA。[官方产品页](https://cloud.baidu.com/product/textmind.html)
- 百度 OCR 产品页称公有云服务可用性 99.9% 以上，但本次没有在公开协议目录中找到“文档抽取”专属、含计算口径和赔付标准的 SLA。因此生产采购前应索取书面 SLA，不应把营销页数字直接写入内部 SLO。[官方 OCR 产品页](https://cloud.baidu.com/product/OCR/general)
- [OCR 服务专项约定（官方 DOCX）](https://bce-doc-on.bj.bcebos.com/bce-documentation/Agreements/%E6%96%87%E5%AD%97%E8%AF%86%E5%88%AB%EF%BC%88OCR%EF%BC%89%E6%9C%8D%E5%8A%A1%E7%9A%84%E4%B8%93%E9%A1%B9%E7%BA%A6%E5%AE%9A.docx)要求：若识别包含个人信息，客户须满足合法、正当、必要并取得个人信息主体有效授权；授权至少涵盖传给百度识别和将结果返回客户；授权材料需向百度报备并保存 6 个月备查。
- 同一专项约定称，除法律法规、监管/司法/审计或条款明确情形外，客户数据、应用及行为日志不会提供给第三方；并提供 7×24 在线工单。但协议也明确不保证识别百分百准确、不中断或满足全部需求。
- 文档抽取成功结果中的临时 PDF 下载链接有效期为 30 分钟；这只说明链接有效期，不代表源文件、任务结果或日志的删除期限。[官方 API 响应说明](https://cloud.baidu.com/doc/OCR/s/klzkwzdch)

### 公开资料无法确认，必须在上线前书面补齐

- 文档抽取 REST API 对上传原文件、解析中间产物、抽取结果和日志各自的精确保存期限及删除完成时限；
- 是否用于模型训练/产品优化、是否可明确选择退出；
- 数据实际处理地域、备份地域、分包商清单和跨境机制；
- 企业客户的数据处理协议（DPA）、安全事件通知时限、删除/导出接口；
- 文档抽取专属 SLA 的可用性口径、排除项、赔付与最大责任。

百度发布的[文字识别在线 SDK 隐私政策](https://cloud.baidu.com/doc/AI_REFERENCE/s/8m3zhy677)说明 SDK 个人信息原则上境内存储，并在服务所需期限后删除或匿名化；但本项目计划调用的是服务端 REST API，不是移动端在线 SDK，**不能把这份 SDK 政策直接当作文档抽取 API 的数据处理承诺**。

简历通常包含姓名、电话、邮箱、住址、生日、身份证号等个人信息，接入前应让法务/安全确认候选人告知与授权文案、最小字段清单、删除机制和供应商合同。无书面留存/训练边界时，不建议直接把真实生产简历全量送入 PoC；先使用脱敏或获得明确测试授权的样本。

## PoC 验收建议

建议先使用免费 200 页额度做 50～80 份、覆盖不同格式和版式的盲测，并设置以下门槛：

- 旧版固定字段不作为目标；目标是项目 `ResumeParserStructured` 校验通过率和业务字段准确率。
- 必测 PDF/DOCX/图片；另测 XLS/XLSX；HTML/PPT/PPTX 应验证 provider 回退。
- 分别统计基础信息、教育/工作/项目经历分组、日期、工作年限、技能数组的准确率，而不是只看“整份成功”。
- 记录提交至成功的 P50/P95、轮询次数、2 QPS 下批量吞吐、失败/超时率、成功计费页数。
- 至少与现有 `ocr-llm`、`aliyun-docmining` 做同文件三路对照；只有在准确率、成本、时延或合规中至少一个维度形成明确收益时再上线。

最终 Go/No-Go 建议：**技术上可做，产品上先 PoC，合规上须先补齐书面数据留存/训练边界；不要接即将下线的旧专用 API。**
