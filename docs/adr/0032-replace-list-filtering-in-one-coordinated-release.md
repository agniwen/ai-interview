# 一次性统一列表筛选，不保留旧筛选协议兼容层

统一所有 DataGrid、人才库和招聘台的筛选规则：按拆分后的原子字段计数，超过两个字段采用 ReUI Filters；只有一两个字段的页面直接展示输入控件。此次改版允许调整前端状态和接口查询契约，但不包含数据库结构变更、迁移或业务数据回填。产品选择前端与相关接口一次性更新，不采用先前建议的新旧筛选协议双轨过渡，因此不为旧筛选请求、旧 URL 参数或旧筛选状态增加兼容转换层。已迁移页面忽略旧混合 search URL 参数，队列任务 ID 的显式 search 例外。

## Consequences

- 发布需要协调所有消费本次筛选协议的前端与接口；旧客户端继续调用旧筛选协议不属于支持承诺。
- 此决定仅针对列表筛选的交互和查询协议，不授权删除业务数据，也不取消历史简历评价的版本解释规则。
- Workspace、Private Resume Pool、Public Resume Pool 等既有数据可见性规则保持有效，用户筛选不能扩大权限范围。
- 用户确认开始实施后，本轮采用基础模式：字段之间 AND；同一字段只允许一个条件；岗位、创建人等多选为 ANY，技能为 ALL。不开放 OR、嵌套条件、否定或接口没有实现的操作符。
- 2026-08-26 补充：混合关键词搜索拆为独立字段，不能在 Filters 外继续保留候选人/公司/学校等混合搜索。招聘阶段也进入 Filters；切换队列资源等页面上下文、权限限定范围不作为可移除的条件。工具栏同一行按“筛选 → 清空筛选 → 刷新 → 其他操作”排列，窄屏自然换行；骨架屏同步。
- 选择展示的字段使用 Jotai atomWithStorage 保存至 localStorage，并设置 getOnInit: true。仅保存资源键与字段键，不保存值、操作符或 rule id。添加空条件也会记住；重置值保留所选条件，移除条件才修改展示配置。
- 单选即时提交，多选及手动日期编辑点击“应用”提交，取消不改查询。人才库日期快捷项立即提交为固定的北京日期范围，翻页不会因跨日改变边界。
- 枚举、日期、多选继续映射到已有查询参数；新增 textFilters 承载原子文本字段的 JSON 对象，按资源白名单校验。文本字段之间 AND、各字段字面包含，过滤先于分页且与 total 使用同一谓词。不引入通用查询 AST API，不更改数据库。ReUI 的 rule id 和未完成条件不进入 URL、请求或 query key。公司/学校复用现有索引预筛，再验证对应字段。
- 修改已生效条件时原子重置页码，并清除旧的批量选择。清空仅清理条件值并保留选中字段、排序及页面上下文；清空或移除默认“未归档”条件都显式请求全部，不能意外恢复默认条件。
- 沿用服务端分页和权限过滤；人才库/招聘台固定行高虚拟列表、日期吸顶、后台刷新逻辑不变。长选项列表复用 ReUI Cascader 的阈值虚拟化。
- Web 与桌面端沿用仓库现有 UI 副本布局，同时更新工具栏及 ReUI 源码；来源与本地调整见 [ReUI Filters 集成说明](../reui-filters.md)。
