# Use the Nest standard HTTP error contract

Nest-owned endpoints in `apps/backend` intentionally replace the existing Hono error payloads with Nest 12's standard HTTP exception envelope: `statusCode`, `message`, optional `error`, and optional stable `errorCode`. Controllers and application boundaries use the most specific built-in `HttpException` subclasses, translate domain and infrastructure failures without leaking internal details, preserve causal errors for logging, and reserve unknown failures for a generic 500 response. Stable domain-specific `errorCode` values allow generated clients to branch without parsing human-readable messages. Validation errors retain Nest's standard array-capable `message` behavior. Better Auth's `/api/auth/**` handler is the explicit exception and keeps its vendor-defined protocol so official clients and OAuth callbacks remain interoperable. This is a coordinated breaking change: cutover requires clients generated from the new OpenAPI contract rather than compatibility with the old `{ error: ... }` payloads.
