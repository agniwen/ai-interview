# Verify the Nest migration with black-box contract parity

The migration will maintain an executable inventory of every standalone HTTP endpoint and background workload, then run black-box parity tests against the unchanged Hono/Worker implementation and `apps/backend`. HTTP comparisons cover methods and paths, request acceptance, status semantics, cookies, CORS, redirects, multipart handling, streams, binary bodies, and download headers; Nest-owned error bodies are instead checked against the new Nest 12 exception contract because that change is intentional. Background comparisons cover queue state, deterministic job IDs, database effects, retries, scheduling, and failure behavior. The existing test suites remain regression inputs but are not sufficient proof of parity by themselves. Full acceptance tests will use isolated PostgreSQL, Redis, and S3-compatible dependencies so both implementations can execute equivalent fixtures without sharing mutable state.
