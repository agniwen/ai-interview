# Preserve health contracts with Nest Terminus

`apps/backend` will use `@nestjs/terminus` with project-owned indicators while preserving `/api/health`, `/api/ready`, `/healthz`, and `/readyz` as compatibility endpoints. Liveness reports process availability; readiness checks only the capabilities enabled for the current replica, so an HTTP-only replica does not fail because background workloads are intentionally disabled. The Worker-compatible readiness endpoint returns a stable `503` reason when background workloads are disabled and otherwise retains the current database, Redis, queue, and feature-configuration checks. Successful response shapes remain compatible; failed Nest-owned health responses follow the later Nest standard error-envelope decision in ADR 0055. Custom indicators avoid exposing dependency credentials or internal error details.
