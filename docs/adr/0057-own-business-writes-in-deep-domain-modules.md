# Own business writes in deep domain modules

`apps/backend` uses seven deep Nest modules—Identity Access, Recruiting Setup, Jobs, Candidate Lifecycle, Meetings, Recruiting Copilot, and Platform Operations—instead of modules shaped by URL depth or one controller family. Every persisted table has one write owner; other modules must use a narrow owner command or projection rather than a shared Drizzle database port. Candidate intake, resume records, recruiting pipeline state, AI and human interview rounds, offers, and notifications remain together in Candidate Lifecycle because interview rounds belong to the Candidate Recruiting Record and several invariants require one transaction. Platform Operations owns no business tables. The existing `studioInterview` table is a transitional persistence detail owned exclusively by Candidate Lifecycle until an expand/backfill/switch/contract migration separates candidate identity, resume documents, and Candidate Recruiting Records. HTTP paths, operation IDs, schemas, and the Nest error envelope remain independent transport contracts.
