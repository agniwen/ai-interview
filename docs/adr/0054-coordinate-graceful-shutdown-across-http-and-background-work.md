# Coordinate graceful shutdown across HTTP and background work

`apps/backend` will use a single drain coordinator rather than relying on incidental Nest module-destruction order. On `SIGTERM` or `SIGINT`, the process first fails readiness, stops schedulers and recovery scans, prevents workers from fetching new jobs, stops accepting new HTTP connections, and waits for in-flight HTTP requests and active BullMQ jobs. It then closes IMAP, Feishu bot, and other long-lived connections before queue clients, Redis, the background and API database pools, and finally Sentry. A configurable total timeout defaults to 120 seconds; if exceeded, the process reports the unfinished components and exits so the existing idempotency, lease, retry, and recovery mechanisms can resume work instead of blocking deployment indefinitely.
