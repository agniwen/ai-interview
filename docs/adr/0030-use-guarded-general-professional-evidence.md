# Use a guarded general professional evidence standard when the JD is silent

Qualitative resume evaluation prioritizes explicit job-description requirements and grounds every dimension judgment in candidate resume facts. When the JD does not define a dimension-specific expectation, the evaluator uses a versioned general professional evidence standard instead of returning an empty description or inventing a hidden job requirement. The fallback covers evidence of skill depth and transferability, responsibility and outcomes, project ownership and complexity, relevant learning foundations, growth and adaptability, and explainable career continuity; it must not assume elite credentials, uninterrupted employment, or low job mobility are inherently superior.

The fallback may produce a substantive positive, mixed, or uncertain dimension narrative, but it cannot by itself produce a not-recommended candidate level. That level still requires an evidence-backed conflict with an explicit core requirement or responsibility in the JD.

The initial qualitative contract enforces dense, resume-factual, JD-aligned dimension narratives through the versioned prompt and normal result-shape validation. It does not add structured per-dimension evidence arrays or source-existence validation in this phase; those remain a possible later hardening step rather than a launch requirement.

Prompt quality is exercised by an independent regression dataset and test script covering rich and sparse JDs, insufficient resumes, explicit core mismatches, bias-sensitive career histories, job-dependent outcomes, optional guidance, and forbidden scoring language. Real-model regression runs are offline release checks only: they do not execute in the production request path, gate user actions, or add product behavior.
