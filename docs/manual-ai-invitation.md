# AI 面试邀请邮件：人工预览并确认

## 页面操作

招聘详情的「面试结果」卡片中，当前 AI 初面提供「复制面试链接」和「发送邮件邀请」两个等宽按钮，使用 flex 和统一 gap。发送入口仅提供给有面试修改权限的人员。

点击发送入口只读取确认信息，弹窗展示候选人、收件邮箱，以及发送包含面试链接的 AI 邀请邮件的说明，不再嵌入完整 HTML 正文。后端仍生成内容快照供确认校验。取消、关闭弹窗不会发信，也不影响招聘推进。

新手动邀请保留既有邮件样式，使用「AI HR 初面邀请」文案，包含公司、候选人和应聘岗位。仅在存在截止时间时显示实际有效期，不将预计面试时间当作截止时间；没有岗位名称时不编造岗位。按钮为「查看面试邀请」，不承诺跳转后一定有接受/拒绝步骤，不使用「随时开始」措辞。旧直发模板及其他通知不变，已确认的邮件仍发送原内容快照。

点击「确认发送」后才创建通知事件及投递，页面按产品口径提示「邮件已发送成功」，并刷新当前候选人的活动记录。接口成功表示入队成功，并不代表已经送达；由 Worker 按现有机制异步调用 Resend，实际结果以通知投递记录为准。

## 安全与去重

- 两个接口均要求登录、工作区作用域、interview/update 及 resumeLibrary/read 权限，并在预览和确认时检查候选人的招聘数据可见范围。
- 预览检查当前有效 AI 轮次、待开始状态、有效邀请及候选人邮箱。
- 确认凭据有效期 10 分钟，签名绑定操作者、工作区、轮次、请求编号和内容指纹。确认时重新读取并比较；内容或邮箱发生变化必须重新预览。
- 同一预览的重复确认使用同一事件去重键和供应商幂等键；重新打开预览再确认表示一次新的人工发送。
- 事件和投递在同一数据库事务中创建，避免只有事件没有收件人。
- 使用既有通知事件 JSON 存储人工确认快照，没有新建表、字段、外键或数据库迁移。
- 人工邮件不引用模板版本表，投递的 templateVersionId 为 null；模板版本号保留在人工确认快照中，不把版本标签当作外键 ID。

## 保持暂停的部分

发起 AI 面试不再自动创建 `ai_interview_invited` 或 `ai_interview_reminder` 通知事件。面试记录、邀请有效期与链接仍正常生成；`ai_interview_invited` 类型继续由人工确认发送入口使用，不删除历史事件或公共消费逻辑。

候选人自动面试邮件和旧队列仍暂停，旧版直发接口仍返回 503。Worker 仅放行新确认接口产生、收件人与内容均匹配的人工 AI 邀请；旧人工标记不放行。HR、面试官通知及 Offer 流程不变。

## 本地验收

Web 与 Worker 应使用同一本地数据库，并同时运行新代码。Worker 需具备有效 Resend 配置并启用通知消费；旧 Worker 会把这类新投递也视为暂停，因此先更新 Worker 再点确认。缺少有效候选人邮箱、失效链接或非当前轮次会显示错误，不会入队。

本次自动化测试隔离邮件供应商，不会真实发送邮件。上线前仍需用授权测试邮箱确认队列消费和收件情况；不要把「已入队」当作送达证明。
